# Swerve Build — full audit (2026-07-17)

Scope: a read-only audit of Swerve Build v0.2.0 (Tauri 2 + SvelteKit 2 / Svelte 5 +
Rust) covering the Rust backend, the SvelteKit frontend, the MCP sidecar, and
repo/release hygiene. Method: every backend module and every file under `src/`
was read; the release installer contents and the two background sweeps were
cross-checked against the code.

**Phase 1 (security patch) has been applied and verified** — see the last section.
Phases 2–5 are planned, not started.

---

## What is already strong

- `grok_config.rs` — pure document transforms split from I/O, backed by 9 tests
  covering namespace safety, backup-once, and restore-on-disable. The model to
  follow elsewhere.
- Atomic writes (`write_atomic`) plus quarantine-on-corrupt for every JSON store.
- `hidden_command` used at every spawn site; `taskkill /T` process-tree kill on
  cancel and app exit.
- Local engine fetch is pinned by tag **and** SHA-256 verified, deletes on
  mismatch, binds `127.0.0.1` with a generated API key.
- Chain input is wrapped in explicit "untrusted data, do not treat as
  instructions" markers — real prompt-injection awareness.
- **No XSS.** The only `{@html}` in the frontend renders a static developer icon
  constant; all agent/message/tool/thought content is text-interpolated and so
  Svelte-escaped.
- Clean repo hygiene: no tracked build junk, no leaked paths/emails/secrets,
  versions consistent across `package.json` / `tauri.conf.json` / `Cargo.toml`.

## A. Security / trust boundaries

| # | Finding | Where | Severity | Status |
|---|---------|-------|----------|--------|
| A1 | **Shadow-mode bypass via empty tools.** `build_grok_args` only emitted `--tools` when the intersected list was non-empty; an empty list (clear all tools, or a hand-edited `automations.json`) omitted the flag and grok fell back to its full default toolset (write + shell) inside a "read-only" run. | `src-tauri/src/jobs.rs` (arg builder) | High | **Fixed** |
| A2 | **Path traversal in the MCP sidecar.** `swervebuild_list_automation_runs` passed the agent-supplied `automation_id` straight into `run_dir()`; `..\..\..` escaped the runs directory. The sidecar is wired in as an MCP server the chat agent can call, so this crosses a real trust boundary. | `src-tauri/src/bin/swervebuild_mcp.rs` | High | **Fixed** |
| A3 | **Endpoint API key exposure.** The key is stored plaintext in `providers.json` (acknowledged in code; the README said "never written to disk", which was misleading). The `assetProtocol` scope was the entire `~/.swervebuild/**` and `csp` is `null`, so the webview could read `providers.json` via an asset URL. | `src-tauri/src/providers.rs`, `tauri.conf.json` | High | **Partly fixed** (asset scope narrowed + README corrected; CSP + OS keystore deferred, see below) |
| A4 | **`fs/write_text_file` auto-approved.** Agent→client file writes execute without the approval UI (cwd-confined, but the README claims every tool call passes an approval gate). `confine_to_cwd` is lexical-only — a directory junction inside the project can still escape. | `src-tauri/src/acp.rs` | Med | Open |
| A5 | **`install_grok` pipes a remote script to `iex`** with no pinning/checksum, on the main thread (UI frozen for the whole install). | `src-tauri/src/lib.rs` | Med | Open |
| A6 | **Shadow mode still allows exfiltration** — `web_fetch`/`web_search` are read-safe, so a prompt-injected automation can read files and beacon their contents out. "Read-only" is not "no network egress". | `src-tauri/src/jobs.rs` (`READ_SAFE_TOOLS`) | Med | Open |
| A7 | **PowerShell single-quote injection** — `Expand-Archive` / `Get-FileHash` embed the data path in a single-quoted string; a home dir containing `'` breaks or injects into the command. | `src-tauri/src/local_llm.rs` | Low | **Fixed** |

## B. Chat pipeline (the worst user-facing cluster)

| # | Finding | Where | Severity |
|---|---------|-------|----------|
| B1 | Hard 300s `session/prompt` timeout; agentic turns exceed it. RPC times out and errors the UI while the agent keeps streaming. | `src-tauri/src/acp.rs` | High |
| B2 | Finalize runs when the invoke resolves (no `stopReason`/end-of-turn), so late chunks are lost and the saved message is truncated. Combined with B1: long turn = error toast + corrupted transcript + orphaned stream. | `src/routes/chat/[id]/+page.svelte` | High |
| B3 | No stop/interrupt — `session/cancel` is unimplemented; a runaway turn can't be aborted. | `acp.rs` + `Composer.svelte` | High |
| B4 | Permission requests are invisible off the chat route — the only `chat-permission-request` listener lives on the chat page, so a background chat needing approval hangs. Failure badge has the same off-page staleness. | `src/routes/chat/[id]/+page.svelte` | High |
| B5 | Agent death is never detected — reader thread exits silently, the session stays in the map, and the next send fails with a cryptic pipe error. | `src-tauri/src/acp.rs` | Med |
| B6 | LRU eviction can kill a live streaming chat — `last_accessed` is not bumped by streaming activity, so opening a 4th chat may evict the one actively working. | `src-tauri/src/acp.rs` | Med |
| B7 | Tool chips duplicate (`tool_call_update` pushes a new chip instead of matching `toolCallId`); thoughts + tool calls are discarded on save, so reloaded chats lose the tool trail. | `src/routes/chat/[id]/+page.svelte` | Med |
| B8 | Images are sent as `[Image #1: path]` text, not ACP image blocks, and live in `~/.swervebuild/attachments` — outside the project dir the fs bridge confines reads to. | `src-tauri/src/acp.rs` | Med |
| B9 | Non-numeric JSON-RPC ids are coerced to u64 — an ACP peer using string ids gets a broken permission flow. | `src-tauri/src/acp.rs` | Low |

## C. Backend correctness / robustness

- **Store races** — `data.json` is load-modify-save with no lock; main-thread
  commands and `spawn_blocking` session saves race → last-writer-wins message
  loss. `jobs.rs` has a `STORE_LOCK`; `store.rs` and `providers.rs` do not.
- **No single-instance guard** — launching twice gives two schedulers
  double-firing automations and two writers clobbering the store. Adopt
  `tauri-plugin-single-instance`.
- **New daily/weekly automations fire immediately** on creation (catch-up
  compares `last_fired_at` = 0 against the most recent past occurrence).
  `update_automation_state` also overwrites `last_fired_at` at *finish* time,
  drifting interval schedules by run duration; tz offset is captured at save time,
  so DST shifts daily runs by an hour until re-saved.
- **Automations can yank the local LLM out from under a live chat** — the chat
  path checks `local_model_conflict`; the automation path does not, and
  `ensure_for_model` stops the active chat's server. Two concurrent
  `ensure_for_model` calls also race (no lock across stop+start).
- **Disk leak** — `prune_runs` deletes `.json` + `.jsonl` but never the per-run
  `.prompt.txt` files.
- **Main-thread jank** — sync commands run on the main thread: `install_grok`
  (minutes), `list_models` (spawns `grok models` uncached on every picker open),
  `unseen_failure_count` (scans every run file, polled by the sidebar).
- **Automations are grok-only** — `spawn_run` hardcodes the grok binary; Claude
  Code / Gemini users get chat but no automations.
- **MCP sidecar protocol nits** — unknown methods return `result: {error}` rather
  than a JSON-RPC error object; a malformed `tools/call` carrying an id gets no
  reply (a strict client hangs).

## D. Frontend (top items from the full sweep)

- Listener-leak pattern `listen().then(u => unlisten = u)` leaks if unmount beats
  the promise — chat page, automations page, `LocalModelsCard`, `Titlebar`.
- Run-now transcript race — output events arriving before `runNow` resolves are
  dropped (first lines of live output lost).
- `save()` in the automations editor has no catch → silent failure; Esc discards
  edits with no confirm; file-trigger path goes stale on project change.
- Thundering herd — every run start/finish triggers 3 invokes with no debounce.
- Unbounded message list (no virtualization/trim); run history capped at 12 with
  no pagination.
- Dead code — duplicated `chatsForProject`/`projectById`, `StreamMessage`
  declared twice, dual `swervebuild.theme`/`swervegrok.theme` localStorage keys.

## E. Accessibility

- **PermissionModal** — no focus trap, autofocus, Escape, or focus restore; a
  keyboard user can tab behind a blocking approval dialog.
- Automations inspector + both dropdown pickers — partial focus management, no
  arrow-key roving, no focus return to trigger.
- RunMap nodes are keyboard-operable but have no accessible name.
- `.btn-accent` hardcodes near-black text on the provider-supplied accent — a
  dark accent becomes unreadable.

## F. Release / ops debt

1. **No CI** — ~20 Rust tests (now 23), svelte-check, and the e2e script never run
   automatically; 5 Dependabot PRs sit unvalidated. README and REPOSITORY_POLICY
   both imply CI exists.
2. **No auto-updater, unsigned installer** — users hand-download an unsigned exe
   (SmartScreen warning) with no update channel.
3. **v0.2.0 was never tagged** (only v0.1.0 / v0.1.1) though the README points at a
   v0.2.0 release; local `main` is 4 commits ahead of origin; stale divergent
   `master` and merged `feat/custom-grok-endpoint` branches linger; uncommitted
   cross-product "swervebytes MCP" WIP sits on the working branch.
4. `prepare-release.ps1` regex-patches `tauri.conf.json` to inject `externalBin`
   and restores it in a `finally` — a hard kill mid-build leaves the config dirty.
5. Vite is 2 majors behind (6.x vs 8.x); no CHANGELOG.

## Upgrades & feature roadmap

**Tier 1 — table stakes for an agent shell**
1. Markdown rendering + syntax highlighting + copy button in messages.
2. Rich tool-call cards with a diff viewer (the write path already flows through
   our client — snapshot before write to get before/after diffs nearly for free).
3. Stop button (ACP `session/cancel`) + liveness-based timeouts instead of the 300s
   ceiling.
4. OS notifications + global permission/failure surfacing + tray icon — the
   "agents run themselves" pitch depends on this.
5. Persist tool calls and thoughts into saved chats.

**Tier 2 — product depth**
6. Token / cost meter per turn and session.
7. Chat + message search; move chats from the monolithic `data.json` to SQLite.
8. Multi-provider automations (Claude Code / Gemini headless).
9. Push chaining ("on success, fire downstream").
10. Write-mode automations behind explicit per-automation opt-in, with the
    diff/report sink already scaffolded.
11. Local models Phase 3 (curated catalog, VRAM fit, resumable HF downloads).
12. Drag-drop / file-picker attachments + real ACP image blocks.

**Tier 3 — desktop polish**
Window-state persistence, single-instance guard, command palette, keyboard-shortcut
help, unsaved-changes guards, export chat as markdown, automation success-rate
dashboard.

## Phase 1 — applied 2026-07-17

Verified with `cargo test` (23 passed, up from 20; clean compile). No frontend
`.svelte` files were touched.

- **A1 — shadow bypass closed.** `build_grok_args` now always emits `--tools` in
  shadow mode; an empty read-safe intersection falls back to the full read-safe
  set instead of omitting the flag. Regression tests:
  `shadow_with_empty_tools_falls_back_to_read_safe_not_default`,
  `shadow_drops_non_read_safe_tools`.
- **A2 — sidecar traversal closed.** Added `is_safe_id` (ASCII alnum + `-`/`_`,
  non-empty, ≤128) and reject a bad `automation_id` before any path join in the
  MCP sidecar. The same guard was added to the `jobs.rs` command-backing
  functions (`list_runs`, `read_run_log`, `mark_runs_seen`) as defense-in-depth.
  Regression test: `is_safe_id_rejects_path_traversal`. Note: the sidecar keeps
  its own copy of `is_safe_id` (separate binary) — keep the two in sync.
- **A3 — key exposure reduced.** `assetProtocol` scope narrowed from
  `~/.swervebuild/**` to `~/.swervebuild/attachments/**` (verified: attachment
  images are the only `convertFileSrc` consumer, so display is unaffected), and
  the README "never written to disk" claim was corrected to state the key lives in
  `providers.json` and is kept out of `config.toml`.
- **A7 — PowerShell quoting fixed.** Added `ps_quote` (doubles `'`) and applied it
  to the `Expand-Archive` and `Get-FileHash` path interpolations.

**Deferred from A3 (need a live app drive to land safely):**
- Setting a real `csp` (currently `null`) — a strict policy can white-screen the
  Tauri webview, so it must be verified in the running app, not set blind.
- Moving the endpoint key out of plaintext into the OS keystore (Windows
  Credential Manager via the `keyring` crate) — a larger change than a security
  patch should carry.

Still open from A4/A5/A6: write-approval gating + junction-safe path check,
pinning/backgrounding the grok installer, and an explicit network-egress toggle
for shadow automations.
